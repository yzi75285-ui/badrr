## 1. 系统是什么

badrr 是一个项目，里面有三层 Agent。三层用 TypeScript 实现。Rust 不构成第四层 Agent，它是监督进程：拉起、超时、预算切断、崩溃隔离、按任务卡限制可写目录。

| 层 | 名称 | 人数 | 职责 |
| --- | --- | --- | --- |
| 第一层 | 主 Agent | 全系统 1 个 | 接收目标，写下五栏决定，派任务，验收，合并。不执行技能 |
| 第二层 | 专家 Agent | 多名。同一职责可以有多人 | 政委给出规则和法律建议，并可冻结红线。将军保存业务记忆，按第一性原则提议放弃部分功能，并监督新技能是否增效 |
| 第三层 | 执行 Agent | 多名。同一基础技能可以有多人 | 组长席决定这一次如何执行。同技能执行者按方案执行。简易工作 Agent 只做该技能中的一步 |

组长是第三层里的席位，不是第四层。现任组长由连续周期的产出决定。原组长被替换后回到同层执行者，性格和已吸收的技能包随本人走。

`D:\badrr\claude-code` 是外部参考目录，不属于这三层的源码，不进入验收范围。

| 监督核心：拉起、超时、预算切断、崩溃隔离、可写目录限制 | Rust 库 | 阶段 1 起按库实现 |

## 3. 主 Agent

### 3.1 性格

性格在创建时写定。换技能、换资料都不改这四栏。要换性格，就新建一个 Agent，不覆盖这一个。

| 栏 | 内容 |
| --- | --- |
| 不可交易项 | 第一责任是为人民服务。没有事实、没有对立面，就不能称为决定 |
| 风险态度 | 军事化决策：一件事只有一个责任人，可以叫停，决定后要复盘 |
| 表达方式 | 决定只写受影响的人、事实、对立面、保留什么、放弃什么 |
| 对放弃功能的倾向 | 合题里可以放弃部分功能。放弃必须写在决定记录里 |

交给人的结果只写事实、规则和取舍。政委、将军、组长这些席位名留在内部记录。

### 3.2 知识图谱

九个学科是知识图谱，不是性格。每个节点只保存带来源的概念、适用条件和出处。没有对应条目时，决定记录写「未证实」，不补一句看起来像该学科的话。

| 节点 | 来源 | 图谱里放什么 |
| --- | --- | --- |
| 语文 · 中文古文与唐诗宋词 | `chinese-poetry/chinese-poetry` | 篇名、作者、正文。范围含诗经、论语、四书五经、蒙学、唐诗、宋诗、宋词 |
| 语文 · 中文诗集 | `Werneror/Poetry` | 朝代、作者、题目、正文。先收先秦到清代 |
| 语文 · 英文公有领域散文 | `aparrish/gutenberg-dammit` | 书目与正文。作为英文古文和较早现代文 |
| 语文 · 英文诗集 | `aparrish/gutenberg-poetry-corpus` | 诗行与所在书目 |
| 数学 · 范围 | `ossu/math` | 证明、微积分、微分方程、离散、线代、概率统计、分析、抽象代数，以及逻辑、几何拓扑 |
| 数学 · 思维 | `OpenLogicProject/OpenLogic` | 命题、量词、推导、集合 |
| 数学 · 正式内容 | `leanprover-community/mathlib4` 与 `leanprover/lean4` | 定理名、依赖、领域 |
| 数学 · 逐步推导 | `metamath/set.mm` | 从公理到定理的证明步骤是否闭合 |
| 物理 · 普通知识 | `openstax/osbooks-university-physics-bundle` | 力学、电磁、波、热学、光学、近代物理的概念、适用条件和公式 |
| 物理 · 常数 | `JuliaPhysics/PhysicalConstants.jl` 所载 CODATA 2022 | 数值、单位、不确定度 |
| 物理 · 分子第一性原理 | `pyscf/pyscf` | 方法名称与适用对象：Hartree–Fock、密度泛函、微扰、耦合簇 |
| 物理 · 固体第一性原理 | `QEF/q-e` | 密度泛函下结构、振动、能带各自能回答的问题 |
| 市场经济 | `microsoft/qlib` | 行情、因子、风险、组合这些概念 |
| 经济运营 | `statsmodels/statsmodels` | 回归、假设检验、预测区间 |
| 政治矛盾 | `networkx/networkx` | 双方及其关系 |
| 客观事实 · 可追溯数据 | `akfamily/akshare` | 数据条目与来源 |
| 市场管理 | `lballabio/QuantLib` | 定价、风险、约束 |
| 生物 | `biopython/biopython` | 已公开的分类、注释和安全边界 |
| 化学 | `rdkit/rdkit` | 结构、描述符、性质分类 |

近现代和当代中文、仍在版权期内的英文作品，不进入图谱，除非另行提供使用权。OpenStax 教材若进入商业用途，图谱只保留概念名和出处，不保留教材正文。市场类来源只提供概念和可追溯数据，不把下单、实盘写成主 Agent 的能力。

政治矛盾、市场经济、市场管理、经济运营、生物、化学的具体资料仍可由后续喂入的材料补全。喂入的材料只增加图谱条目，不改第 3.1 节的性格。

## 4. 第二层与第三层

### 4.1 专家 Agent

| 席位 | 可以做 | 不能做 |
| --- | --- | --- |
| 政委 | 依据客观事实提出规则和法律建议。方案或新技能触及已登记红线时，冻结该方案或该技能 | 不改目标，不指挥执行步骤，不向用户交付最终结果 |
| 将军 | 保存与对接过程中沉淀的业务记忆。按第一性原则提议放弃部分功能。用同一夹具核对新技能是否增效，未增效则叫停 | 不代替主 Agent 做最终决定 |

同一职责可以有多名专家。连续 3 个可比周期里挑战者更好，则更换该职责的现任。这套计数不把专家称作组长。

### 4.2 执行 Agent

| 席位 | 可以做 | 不能做 |
| --- | --- | --- |
| 组长 | 决定这一次如何执行，并把执行派给同层同技能执行者，或派给简易工作 Agent | 不改目标，不把任务派到其他技能组 |
| 同技能执行者 | 按组长方案执行，把结果交回组长 | 不把任务再转给另一个同层执行者 |
| 简易工作 Agent | 执行登记卡上的一步，返回这一步的结果 | 不调用模型，不持有记忆，不再派子任务 |

同一步可以有多个简易工作 Agent。他们的差别来自附加技能包，基础技能标识保持相同，这样才可以比较产出。

## 5. 调用与上下文

派工只沿层往下，结果只沿层往上。

1. 用户把目标、约束、预算交给主 Agent。
2. 主 Agent 写五栏决定，再把领域任务派给现任专家。
3. 专家把一项技能任务派给该技能的现任组长。
4. 组长派给同技能执行者，或派给简易工作 Agent。
5. 结果按原路返回。主 Agent 写出最终结果。

主 Agent 不直接调用组长或简易工作 Agent。专家不直接调用简易工作 Agent。同层之间不互相通话，组长对同技能执行者的这一次派工除外。执行者不能再转派。

各层看见的上下文：

| 层 | 看得见 |
| --- | --- |
| 简易工作 Agent | 这一步的输入 |
| 组长与同技能执行者 | 这一次技能任务，以及被派到的步骤结果 |
| 专家 | 本领域任务，以及下属组长交回的技能结果 |
| 主 Agent | 目标、约束、各专家交回的领域结果 |

## 6. 必须落地的记录

字段名在阶段 1 冻结。后续只能增加可选字段，不能改已有字段的含义。

### 6.1 决定记录

主 Agent 每次决定都有一份记录，五栏缺一不可。

| 字段 | 含义 |
| --- | --- |
| `decision_id` | 决定标识 |
| `affected` | 受影响的人 |
| `facts` | 事实依据，每条带出处标识 |
| `opposition` | 对立面 |
| `keep` | 保留什么 |
| `drop` | 放弃什么。没有放弃时写明「不放弃」 |
| `freeze` | 政委冻结及理由。没有冻结时为空 |
| `stop` | 将军叫停及理由。没有叫停时为空 |
| `status` | `draft`、`frozen`、`accepted`、`rejected` 之一 |

冻结之后，主 Agent 要改方案，或在本记录里写明例外和理由，才能把状态改为 `accepted`。

### 6.2 任务卡

一张任务卡只有一个执行者，并带有目标。

| 字段 | 含义 |
| --- | --- |
| `task_id` | 任务标识 |
| `decision_id` | 所属决定 |
| `assignee_id` | 唯一执行者 |
| `goal` | 这一张卡要完成的目标 |
| `allow_paths` | 允许修改的目录 |
| `deny_paths` | 禁止修改的目录。至少包含 `.git` |
| `done_when` | 怎样算做完 |
| `budget` | 剩余预算 |

### 6.3 Agent 登记卡

| 字段 | 含义 |
| --- | --- |
| `agent_id` | 标识 |
| `layer` | `main`、`expert`、`executor` 之一 |
| `seat` | `main`、`commissar`、`general`、`leader`、`peer`、`worker` 之一 |
| `parent_id` | 父级。主 Agent 为空 |
| `personality` | 四栏性格。创建后不可改 |
| `base_skill_id` | 基础技能。主 Agent 为空 |
| `addon_skill_ids` | 附加技能包 |
| `input_schema` | 输入契约标识 |
| `output_schema` | 输出契约标识 |
| `version` | 卡片版本 |

### 6.4 步骤结果

| 字段 | 含义 |
| --- | --- |
| `status` | `done`、`refuse`、`error` 之一 |
| `output` | 输出 |
| `evidence` | 出处或夹具标识 |
| `cost` | 代价，含返工和预算 |
| `error` | 失败原因。成功时为空 |

## 7. 换届与新技能

一个周期等于一次已被上层验收的同类任务。任务类型不同，不计入挑战。平局留任。

更好指：通过率不降且代价下降，或代价不升且通过率上升。默认连续 3 个周期才更换现任。阶段 2 结束前只记账，不自动换人。

新技能先进入隔离区。政委判断它是原技能的附加包，还是另一项新技能。将军用同一夹具核对接不增效。主 Agent 批准后，附加包才挂到某个 Agent 身上。判定为新技能的，另开技能组，不参与原组换届。未增效的技能留在拒绝记录里。外部代码不直接进入运行中的 Agent。

## 8. Rust 监督

监督库提供这些调用，桌面宿主和以后的 iOS 宿主都走同一套接口：

| 调用 | 行为 |
| --- | --- |
| 拉起 | 在指定工作区启动一个 TypeScript Agent 进程 |
| 超时 | 到期结束该进程，并返回 `error` |
| 预算切断 | 预算耗尽时结束该进程，并返回 `error` |
| 崩溃隔离 | 一个简易工作进程崩溃时，只失败这一步 |
| 可写目录 | 只允许任务卡 `allow_paths` 内的写入。`.git` 保持只读 |

阶段 1 的宿主实现拉起、超时和追踪。阶段 2 接上预算切断。阶段 3 让外部技能只在该沙箱中运行，批准后才成为附加技能包。

监督库不读取性格，不改写五栏决定，不选择组长。

## 9. 目录

```text
badrr/
  docs/                 本验收说明
  contracts/            JSON Schema
  decisions/            五栏决定与任务卡。只由主 Agent 写入
  registry/             登记卡与知识图谱条目
  control/              TypeScript：三层 Agent、换届账本、命令行
```

阶段 1 可以先只有 `docs/`、`contracts/`、`decisions/`、`registry/`、`control/`、`supervisor/`。`agents/` 里的技能实现随第三层的第一张任务卡出现。

## 10. 分阶段验收

### 阶段 1：主 Agent 与整树席位

通过线：

1. 一条命令读入一个目标，主 Agent 写出一份五栏齐全的决定记录。
2. 缺任何一栏时，命令失败，并且不产生 `accepted` 状态。
3. 登记卡能表达三层、六种席位和四栏性格。
4. 样例树能跑通：1 个主 Agent、1 名政委、1 名将军、1 个组长、1 个同技能执行者、2 个不同步骤的简易工作 Agent。业务名称可以使用夹具名。
5. 追踪里能看到从主 Agent 到简易工作 Agent 的下行，以及原路返回。
6. Rust 监督程序能拉起该进程，超时后返回 `error`，并留下追踪。
7. 简易工作 Agent 的实现里没有模型调用。

本阶段专家、组长和简易工作都用确定性规则，不接模型，不接外网。

### 阶段 2：监督生效

通过线：

1. 专家和组长可以调用同一个 TypeScript 模型适配器。简易工作 Agent 仍然不调用模型。
2. 同一夹具能算出通过率和代价。
3. 预算耗尽时，Rust 监督切断进程，决定记录或步骤结果里看得到原因。
4. 一条人工放入隔离区的新技能走完分类、增效核对和主 Agent 批准。未增效的进入拒绝记录。
5. 任务卡之外的路径写入被监督程序拒绝。

### 阶段 3：换届与外部技能

通过线：

1. 连续 3 个可比周期更好的挑战者自动接任，原任回到同层。
2. 外部技能只能作为候选进入隔离区，并走阶段 2 的同一条批准路径。
3. 看板能显示现任、挑战记录、冻结和叫停原因。
4. 一个简易工作进程崩溃时，其余席位仍在，只有该步为 `error`。
