# 弥知

弥知是本机上的中文阅读台。读者上传或打开自己有权阅读的书，选中原文，和四个角色谈话，再把自己的取舍写成读后卡片。英文名写在文件夹里：`弥知 · Mimir`。界面品牌是「弥知」，小字是 READING。

这份文档是下一位 agent 的交接说明。改产品前先读完。行为以这里和当前代码为准。

## 文化属性

弥知是私人书斋，不是课堂、题库或评分器。旧的学习考核原型已经撤掉，不要把知识点、自测、复测或评分加回来。

读书的伦理是：原文在前，角色各守边界，结论留给用户。

- **作者**只根据选段和邻近上下文揣摩原作者希望读者理解什么。每个判断引用选段里的连续原句。选段撑不住时写「本意无法确定」，并指出缺的是哪一句。不补书里没有的生平、动机或后记。
- **理性读者**只检查概念、条件和推论是否被原文支撑。不写个人感受。这段主要是情绪、语气或联想时，保持沉默。
- **主观读者**只讲这一段引起的感受、语气、联想或抗拒，并指出是哪一句引起的。感受不等于作者的主张。这段只是概念分析时，保持沉默。
- **读伴**是用户的同伴，最后发言。先看见用户的原话、作者，以及这一轮真正开口的读者，再说自己看到的差别，并问用户一句取舍。读伴不替用户写成结论。

谈话默认先发给作者。理性读者和主观读者按内容决定是否开口；两者都涉及时一起开口。读伴在他们之后说。用户自己的话必须原样留下。

书只收读者有权使用的文本。架上预置的是公有领域《论语 · 学而》。自动获取只走公有领域来源，目前是古腾堡计划第 11 号《Alice's Adventures in Wonderland》。上传限于 `.txt`，来源和权利由用户声明。不要接入盗版站或来路不明的「免费书库」。

读后卡片是书架日记。作者、理性读者、主观读者的话可以抄进卡片，栏位可以空着。必填的是用户自己的调节，也就是卡片上的那句取舍。模型不代写这一栏。

界面同时用两种气质。操作像 iOS：系统无衬线、大标题、推入过渡、手机底栏、iPad 左侧栏、安全区、可点区域足够大。阅读像一张暖纸：米色纸面、深墨色、衬线正文。强调色是陶土色 `#c96442`，链接和选区用系统蓝。图案是弥知自己的一族，默认「花开」：深色圆角方块上的一朵不对称实心花。十个图案是花开、双页、折角、种子、三锋、扇页、缺口、一叶、对望、星页，存在 `src/gallery.tsx`，选择记在 `localStorage` 的 `mizhi-mark`。用户还没有选定最终图案。`public/icon.svg` 保持现在的花开，在用户选定之前不要改。不要临摹 Claude 的橙色星标，也不要使用 SF Symbols。页内图案是这一族的活形态，可以轻轻变化，但仍然要能认出是同一个标记。

界面文案和四个角色的回复都用中文。语音识别语言是 `zh-CN`。英文书可以原文上架，谈话仍然用中文进行。

数据留在这台电脑。一个 SQLite 文件，不引入 Redis、Docker、MySQL 或其他中间件。

## 框架

Node.js 22.13 或更高。前端是 Vite 6、React 19、TypeScript。后端是 `tsx` 跑的 Node HTTP 服务，数据库是 `node:sqlite` 的 `DatabaseSync`，WAL 模式。没有 Zod，请求在 `server/index.ts` 里手写校验。

`npm run dev` 跑 `scripts/dev.mjs`，同时拉起两个进程：

- API：`server/index.ts`，`0.0.0.0:4317`。改服务器文件后要重新运行 `npm run dev`，这个进程不会热更新。
- 网页：Vite，`0.0.0.0:5178`，`host: true`。`/api` 代理到 `127.0.0.1:4317`。前端改动由 Vite 热更新。

`MIMIR_PORT`、`MIMIR_WEB_PORT` 可改端口。`MIMIR_DATA_DIR` 可改数据目录，默认 `.data`。

只接受本机和私网来源：localhost、127.0.0.1、`::1`、10.0.0.0/8、192.168.0.0/16、172.16.0.0/12。

四个角色都调用 xAI Responses API：`https://api.x.ai/v1/responses`，模型 `process.env.XAI_MODEL`，缺省 `grok-4.7`。只读取 `XAI_API_KEY`。密钥可以在项目 `.env`，也可以在已经存在的环境变量里。`.env` 不覆盖已经存在的环境变量。系统里其他供应商的密钥保持不动，不能拿去调用 Grok。不要把密钥写进仓库、日志或回复。`.env` 与 `.data` 已在 `.gitignore`。

`POST /api/speak` 忽略单独的角色参数，每次走一整轮。`server/grok.ts` 的 `discussRound` 要求一个 JSON 对象，字段是 `author`、`rational`、`subjective`、`companion`。空字符串表示该读者这一轮沉默。作者必填。消息按这个顺序追加：用户、作者、非空的理性读者、非空的主观读者、读伴。邻近上下文是选段前后各约 700 字。历史只带最近 8 条。没有密钥时返回中文错误，输入框里的草稿保留。`askGrok` 仍在文件里，当前页面不走它。

### 目录

- `server/index.ts`：路由与局域网限制。
- `server/store.ts`：SQLite。表是 `books`、`dialogues`、`cards`、`meta`，前三张表都是 `id` + `json`。
- `server/grok.ts`：模型与四角色边界。
- `server/seed.ts`：《论语 · 学而》全文，以及爱丽丝的古腾堡地址。
- `server/types.ts`、`src/types.ts`：同一套类型。前端展示名在 `roleLabels`。
- `src/App.tsx`：书架、阅读、目录、谈话、卡片、语音和浮动标记。页面逻辑都在这一个文件。
- `src/api.ts`：前端请求。
- `src/gallery.tsx`：十个图案。
- `src/styles.css`：纸色、陶土色、iOS 式导航。768px 及以上是 iPad 左侧栏，底栏隐藏。
- `public/icon.svg`：应用图标，目前是花开。
- `index.html`：中文、`viewport-fit=cover`、可加到主屏幕。

### 接口

- `GET /api/health`：进程与模型是否就绪。
- `GET /api/bootstrap`：书架摘要、全部对话、全部卡片、模型名和是否已配置密钥。
- `GET /api/books/:id`：含正文。
- `POST /api/books`：上传。书名、作者、正文必填。正文最长约 150 万字。
- `POST /api/books/acquire`：获取爱丽丝。已有同一 `source` 时直接返回。
- `POST /api/speak`：一轮谈话。选段必须能在正文里原样找到。
- `POST /api/cards`：保存卡片。`synthesis` 必填。

没有删书、删对话、删卡片的接口。

## 页面契约

这些交互已经定下来。改动时保持它们成立，并在浏览器里自己走一遍。

每次打开先播一段开场，大约五秒，右上角可以跳过。书架上的「再看开场」会再播一次。刷新页面也会重播。系统要求减少动态效果时直接进入书架。开场从黑天、黑色流动的海和移动的黑云开始。画面中间的一点展开成弥知的花，这朵花是太阳。随后天空、云和海水过渡到暖调：暮紫、珊瑚、米色的云、青绿的海。开场在 `src/Dawn.tsx`。

书架上的书点一下打开。收在书匣里的书不能从正方形直接进入，要点开书匣，再点那一本。长按书再拖动，可以放进书匣，也可以从匣里拖回书架。书匣平时是正方形，书按书脊立在一条细边上，书名竖写；长按书匣会像整理手机桌面一样晃动，拖动时其他书匣让开。点开才展开。匣身是一张暖纸，和布面封面区分开。一本书同时只在一个匣里。书匣顺序和成员记在 `mizhi-bookcases`。正文按空行分段，约每 320 字为一页，不把一段拆开。左右滑动在没有选中文字时翻页。

目录按页分组。顶栏固定书名、总页数、总段数和当前页。当前页标成「第 n 页 · 当前」。一行是一段：说话人在上，原文摘要在下；没有说话人时用开头十几个字。点一行会翻到那一页，并滚到那一段。

选中至少两个字、且这几个字确实在正文里时，出现「谈这段」。谈话窗的发送按钮写着「发给作者」。读伴的提示说明另外两位读者按内容开口，读伴在后面说。

文章上的弥知按钮：点一下开始语音，定位文中所有匹配段落，并以摘录条列出。匹配时去掉标点，整段包含、被包含，或共享连续 6 个字都算命中。长按约 420 毫秒后拖动，松手把位置写入 `mizhi-float`。没有双击拖动。短按松手才开始听。电脑用 Chrome，iPhone 用 Safari。

手机宽度使用底栏，阅读和目录要留出底栏和安全区。iPad 宽度使用左侧栏，目录是右侧纸片。不要做只能靠悬停才出现的操作。

读后卡片从谈话窗进入，保存后回到卡片页。卡片页按书分成卡片匣，只收这本书的卡片。点开匣子弹出一层，卡片排成唱片：中间一张最大，左右露出相邻的卡片，滑动或点旁边那张就转过去。点中间的唱片或「看全文」进入这一张。

## 打开

```powershell
cd "D:\badrr\弥知 · Mimir"
npm install
npm run dev
```

浏览器打开 http://127.0.0.1:5178 。类型检查是 `npm run check`。

iPhone 或 iPad 和这台电脑连同一个 Wi-Fi，用 Safari 打开 Vite 终端里 `Network` 那一行。上次这台机器的无线网地址是 http://192.168.31.174:5178 ，地址变了就以终端为准。`198.18.*`、VMware 和 WSL 的地址不要发给手机。打不开时，在 Windows 防火墙里允许 Node.js 访问专用网络。

Grok 4.7 使用 `XAI_API_KEY`。还没有这把钥匙时，页面写明尚未连接；发送会失败，草稿留在输入框。填写后重新运行 `npm run dev`。

`.data` 里可能还留着旧考核库 `mimir.sqlite`。它不属于弥知，不要读进阅读库，也不要删掉，除非用户明确要求。

## 接手时先守住的事

- 先读这份文档，再改代码。产品边界以「文化属性」和「页面契约」为准。
- 服务器改动要重启 `npm run dev`。前端改动看 Vite。
- 改界面后在浏览器里走通：书架、打开《论语 · 学而》、翻页、目录跳转、选段、谈话窗、卡片入口、弥知按钮的点按与长按。手机宽度和 iPad 宽度都要看。
- 不要改 `public/icon.svg`，除非用户从十个图案里选定了一个。
- 不要提交 `.env`、`.data` 或任何密钥。用户没有要求时不要做 git commit。
- 不要为了「接上模型」去借用别的供应商密钥。

## 已知缺口

- 本仓库没有可用的 `XAI_API_KEY`，谈话还不能真正跑通。
- 古腾堡下载可能失败，爱丽丝不一定在架上。
- 十个图案里，花开是唯一已经做成应用图标的。其余图案在小尺寸上还参差，等用户选定后再统一。
- 卡片和书还不能删除。
- 语音要在真机 Safari 或电脑 Chrome 上才能听完一句；自动化浏览器里通常没有麦克风。
