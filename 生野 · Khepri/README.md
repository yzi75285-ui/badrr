# KHEPRI

自用运动分析的第 1 段：在电脑浏览器里上传照片和视频，服务端保存原片、做预处理，并提供回看。

动作分析、对比、练习复测和个人 Agent 还没有做。素材记录里的分析状态固定是 `not_implemented`，页面不会把它显示成完成。报告、训练记录和个人记忆的接口已经留好，当前只返回空列表；创建请求会明确拒绝。

手机端不在这一段。以后的 iOS 客户端沿用这里的标识和授权地址：素材 `med_`、任务 `task_`、报告 `rep_`、训练记录 `trn_`、记忆 `mem_`。访问原片和预览要用接口返回的地址，不使用服务端磁盘路径。

产品范围以 `D:\badrr\docs\自用运动分析技术探索.md` 为准。本文件说明现行代码、文化约束和接手边界。

## 名称与文化

文件夹名是 `生野 · Khepri`。程序、接口和环境变量仍用 KHEPRI。

生野取「生」和「野」：人在场地上发生、生长。Khepri 是埃及神话里把太阳推过地平线的圣甲虫，对应日出、新生和持续向前。两者合在一起，是给一个人反复使用的运动记录，不是通用健身课，也不是医疗诊断。

文化上保持这些判断：

- 未知就留空或写成未知。不把没测到的角度、时间、力量补成事实。
- 照片只做静态观察。慢放、变速或时间轴不可靠的视频，不提供依赖真实时间的指标。
- 观察、解释、练习分开写。预处理完成不等于动作分析完成。
- 变化要能回到原片和计算版本。落在测量波动里的差异，写成无明确变化。
- 疼痛和异常只进入人工确认，不由动作模型下诊断。

视觉沿用同一套：奶油底 `#F3EEE6`，陶土色 `#D4724E`，圆头笔画，少图形。母题是升起的太阳、托起太阳的弧、圣甲虫、地平线、破土和路。图标不放文字。「生野」二字用安静的衬线体，深褐色，与图形分开。参考图在 `C:\Users\Administrator\.cursor\projects\d-badrr\assets\`，文件名以 `shengye-` 开头。

## 框架

六段验收顺序是：素材、动作分析、动作对比、训练复测、个人 Agent、iPhone 客户端。现在只实现第 1 段。第 2 段及以后不要在界面上显示成完成。

`npm run dev` 和 `npm start` 只启动这两部分：

| 目录 | 职责 |
| --- | --- |
| `web/` | React 页面。选择、上传、列表、回看、失败后的重试和删除 |
| `server/` | Node 内置 HTTP。接收原片、写任务状态、探测媒体、生成预览 |
| `contracts/` | JSON Schema。字段含义冻结，以后只能加可选字段 |
| `samples/` | 合成样本，用来检查流程 |
| `var/` | 本机数据。不进入版本库 |
| `验收记录/` | 已经跑过的样本测试。本人实拍验收仍待测 |

一条素材的状态是：已接收、预处理中、可回看、失败。上传必须以服务端收齐文件为准。页面关闭不取消已接收的任务。重试沿用原来的 `task_`，只增加尝试次数。原片和预览分开存放。对外只给资源标识和带 `access` 的地址。

`src/` 里有一份未接入上述脚本的 Fastify 与 SQLite 草稿，端口也不同。它不是当前产品。不要同时改两套，也不要在未获要求时把运行入口换成 `src/`。`docs/开发决策.md` 里写到 Fastify 与 SQLite 的句子，指的是这份草稿，不是 `npm run dev` 正在跑的服务。

不要改同级的 `弥知 · Mimir`。那是另一个项目。

## 启动

需要 Node.js 22。在 `生野 · Khepri` 目录：

```powershell
npm install
npm run dev
```

浏览器打开 http://127.0.0.1:5173 。接口在 http://127.0.0.1:4780 。

只启动一个进程、由服务端托管已经构建的页面：

```powershell
npm start
```

然后打开 http://127.0.0.1:4780 。数据默认写在这个目录下的 `var`，可用 `KHEPRI_DATA`、`KHEPRI_HOST`、`KHEPRI_PORT` 改位置和端口。服务只监听本机。

预处理使用随依赖安装的 ffmpeg / ffprobe。普通 JPEG、PNG 在没有它们时仍能回看。HEVC、HEIC 和需要转码的视频会失败并留下原因，装好后对同一份素材重试，不会新建一条任务。

## 这一段能做什么

1. 上传照片或视频，填写篮球或短跑、动作和拍摄条件。未知条件留空。
2. 服务端收齐文件后才记为已接收。页面关闭不会取消已经接收的任务。
3. 保留原片，另外生成预览。记录编码、旋转、尺寸、时长和抽样帧时间戳。
4. 检查 iPhone 常见容器，以及慢放、变速、不稳定时间轴。不能恢复真实时间时会写明，这一段本来也不提供时间指标。
5. 列表和详情在刷新、重启后仍在。失败可以看原因、重试或删除。

检查：

```powershell
npm test
npm run check
npm run accept
```

`npm run accept` 用 `samples/` 里的合成篮球照片和短跑视频跑一遍，并把结果写到 `验收记录/阶段1-样本测试.md`。这不是本人实拍，本人使用验收保持待测。

## 接口

| 方法 | 路径 | 第 1 段 |
| --- | --- | --- |
| GET | `/api/health` | 可用 |
| GET | `/api/capabilities` | 可用 |
| POST | `/api/media` | 上传。请求头 `Idempotency-Key` 相同则返回已有素材 |
| GET | `/api/media` | 列表 |
| GET | `/api/media/:id` | 详情 |
| DELETE | `/api/media/:id` | 删除 |
| POST | `/api/media/:id/retry` | 失败后重试，可附带替换文件。沿用原任务 |
| GET | `/api/media/:id/original?access=` | 原片。支持 Range |
| GET | `/api/media/:id/preview?access=` | 预览。支持 Range |
| GET | `/api/tasks` | 预处理任务 |
| GET | `/api/reports` | 空列表，`implementation` 为 `not_implemented` |
| POST | `/api/reports` | 501 |
| GET | `/api/training-records` | 空列表 |
| POST | `/api/training-records` | 501 |
| GET | `/api/memories` | 空列表 |
| POST | `/api/memories` | 501 |

契约在 `contracts/`。已有字段的含义不再改，以后只能加可选字段。个人记忆的 `kind` 预留为 `stated`（本人陈述）、`inferred`（推测）、`measured`（测量）。
