用户指定在现有工作区下的 `生野 · Khepri` 文件夹继续开发，并允许对不合适的实现重写。当前目录为 `D:\badrr\生野 · Khepri`。Mimir 是另一个用途的前端，Claude Code 是参考代码，均不作为本项目的实现。

交付顺序为网页与服务端先行，iPhone 17 Pro 客户端最后。第一段实现素材上传、保存、预处理、回看及失败恢复。

## 第一段技术选择

现行可运行代码在 `server/` 与 `web/`：网页是 React 与 TypeScript，服务端是 Node 内置 HTTP，素材和任务写入 `var/` 里的 JSON 文件，媒体文件单独保存。FFmpeg 和 FFprobe 负责元数据读取与兼容预览生成。根目录的 `npm run dev` 启动的是这一套。

`src/` 中另有一份 Fastify 与 SQLite 草稿，尚未接入启动脚本。在明确决定切换之前，不把它当作当前产品。

采用独立接口连接网页和服务端。上传、任务状态与媒体访问不依赖浏览器本地存储；后续手机客户端可以沿用接口。文件系统路径只留在服务端。

服务端先在本机运行，只监听回环地址。远程部署、认证、后台长视频上传和 iOS 分发分别在对应阶段验证。

## 与早期 Agent 工程文档的关系

本次交付是运动产品第 1 段，不宣称通过原三层 Agent 系统的工程验收。第一段不需要模型调用，暂不引入多 Agent 编排和 Rust 监督进程。开始执行模型及外部技能时，另行落实任务预算、超时、隔离和审查边界。

GPT、Grok、DeepSeek 的候选分工保留在选型讨论中；模型输出不参与本次媒体预处理。后续接入时在服务端验证账户实际支持的型号、工具和结构化输出，并通过统一契约接收结果。

## 证据原则

原始文件与预览转码分别保存。预处理状态、元数据和用户说明均可回查。预处理成功不产生动作分数、技术诊断或训练建议。

合成素材用于验证软件行为；本人运动素材用于验证使用体验；带人工基线的专项素材用于验证运动分析。三类证据分别记录。
